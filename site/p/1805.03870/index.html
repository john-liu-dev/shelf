论文提出 Conflux，一个快速、可扩展且去中心化的区块链系统，能乐观地并发处理区块而不把任何区块当作分叉丢弃。其共识协议用有向无环图表示区块关系并就区块的全序达成一致，再由区块顺序确定性地导出交易全序作为账本。在最多 2 万个全节点的 Amazon EC2 集群上评测，吞吐为每小时 5.76GB，确认交易需 4.5–7.4 分钟，约相当于典型比特币交易每秒 6400 笔；结果表明共识协议不再是吞吐瓶颈，瓶颈转为单个节点的处理能力。

HN 为什么提它

HN 上有评论者把它列为正在研究的替代共识设计之一，用来说明有方案能达到每秒数千笔交易，并认为 BCH 不是真正的竞争者。

学习路径

这条路径从比特币共识的已知缺陷出发，再看两种改进共识的方案，Conflux 的 DAG 并发区块设计正是针对这些问题提出。

    Majority is not Enough
    Majority is not Enough: Bitcoin Mining is Vulnerable多数并不够：比特币挖矿存在漏洞 · 2013

    它指出分叉和孤块会带来安全问题，是理解 Conflux 为什么要保留而不丢弃分叉区块的背景。

    读区块链分叉与自私挖矿的收益分析；理解分叉率与安全性的关系。

  2. 2
    Enhancing Bitcoin Security and Performance with Strong Consistency via Collective Signing
    Enhancing Bitcoin Security and Performance with Strong Consistency via Collective Signing通过集体签名增强比特币的安全性与性能，实现强一致性 · 2016

    ByzCoin 是改进比特币共识延迟与吞吐的代表方案，可与 Conflux 的思路对比。

    读集体签名与区块确认机制如何缩短确认时间，以及它在吞吐上的限制。

  3. 3
    Algorand
    AlgorandAlgorand · 2016

    Algorand 是另一类用拜占庭共识实现几乎不分叉的方案，是 Conflux 对比的另一条路线。

    读密码学抽签选出委员会与拜占庭共识的整体流程；对比它与 DAG 并发路线的取舍。
