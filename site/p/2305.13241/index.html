编译器在编译速度与代码质量之间存在固有权衡，在 JIT 场景下更为明显，因此许多系统采用多层编译。自 2017 年 WebAssembly 进入 Web 平台以来，所有 Web 引擎都新增了 Wasm 的“基线”编译层以缩短启动时间。论文解释单遍（single-pass）Wasm 编译器的内部算法与权衡，并对生产环境中的这类编译器做了详细实证研究；还给出研究用 Wasm 引擎中一个与原位解释器、宿主垃圾回收器结合的新单遍编译器，借助值标签（value tags）并支持灵活的插桩，实验中针对值标签的优化可把运行时开销降到接近零，并比较了六个基线编译器的编译速度和执行时间。

作者本人在评论中贴出该论文，并说明其用散点图展示了编译准备时间与代码质量的权衡；另有评论提到他此前关于 Wasm JIT 的论文曾在 HN 上被讨论过。

候选里与单遍基线编译相关的只有两篇：快速编译的 copy-and-patch 技术，以及 Wasm 的原地解释器，足以建立编译层级的背景。

  1. 1
    Copy-and-Patch Compilation
    Copy-and-Patch Compilation: A fast compilation algorithm for high-level languages and bytecodeCopy-and-Patch 编译：面向高级语言和字节码的快速编译算法 · 2020

    它代表另一条思路：用预编译模板拼接获得极快的编译速度，可与 Wasm 单遍基线编译器对照。

    读编译速度与代码质量的权衡，以及模板拼接的基本思想；不必深究 LLVM 细节。

  2. 2
    A fast in-place interpreter for WebAssembly
    A fast in-place interpreter for WebAssembly2022

    Wasm 引擎里解释器是比基线编译器更低的一层，理解它才能看懂多层编译的取舍。

    读原地解释器如何直接执行 Wasm 字节码，不先翻译成内部表示，以及与编译层的对比。
