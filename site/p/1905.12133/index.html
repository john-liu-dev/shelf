论文提出将健壮的流处理纳入 SQL 标准的三点方案：以时变关系作为传统表和流数据的统一基础，引入事件时间语义，以及一小组用于控制时变查询结果物化的可选关键字扩展。作者以 Apache Calcite、Apache Flink 和 Apache Beam 的实现经验和教训为例，说明只需这些最小的补充，就能用完整的标准 SQL 语义做流处理。

HN 为什么提它

评论者把它当作流式 SQL 的综合介绍，尤其引用其中 6.5 节的物化控制，也用它来对照 Materialize 等系统是否支持滚动窗口之类的流语义，尽管有人并不完全认同其模型。

方法难度 3 / 5约 45 分钟经得起时间

2流处理基础（stream processing）
3事件时间与水位线（event time / watermark）
4窗口与物化视图（materialized view）
