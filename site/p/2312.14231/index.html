论文访谈了 26 位在不同公司负责构建产品 Copilot 的专业软件工程师，发现工程流程的每一步都有痛点，现有开发实践难以应对 AI 应用的挑战与规模。随后作者组织小组头脑风暴，讨论面向更广泛软件工程社区的机会与工具设计。

学习路径

读这篇之前，按顺序读书架上的 4 篇 · 参考文献来自 OpenAlex，顺序和要点由 Claude Code 排出

这条路径先理解产品 Copilot 的核心技术之一 RAG，再看提示链工具与提示编程这两类开发工具，最后读本文对 26 位工程师的访谈。

  1. 1
    Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks
    Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks面向知识密集型 NLP 任务的检索增强生成 · 2020

    产品 Copilot 常用检索增强来加入用户特定的上下文，这是其代表性技术。

    读检索器加生成器的整体结构，以及外部知识如何补充模型的参数化知识。

  2. 2
    PromptChainer
    PromptChainer: Chaining Large Language Model Prompts through Visual Programming2022

    展示用可视化编程串联多个 LLM 提示，是工程师搭建 Copilot 时会遇到的工具形态。

    读提示链的概念、可视化界面支持的操作，以及用户研究中暴露的难点。

  3. 3
    Prompting Is Programming
    Prompting Is Programming: A Query Language for Large Language Models2022

    把提示视为程序，反映开发 LLM 应用时对更结构化提示工程的需求。

    读查询语言如何把约束与脚本化交互写进提示；理解其设计动机即可。

  4. 4
    ChainForge
    ChainForge: A Visual Toolkit for Prompt Engineering and LLM Hypothesis Testing2023

    面向提示工程与假设检验的工具，对应本文关心的提示测试与评估痛点。

    读如何并行比较多个提示或模型的输出，以及工具支持的评估流程。
